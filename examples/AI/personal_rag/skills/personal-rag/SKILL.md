# Personal RAG: работа с документальным хранилищем

Этот скилл — про добавление документов в личное RAG-хранилище,
обновление и удаление. **Поиск — не через скилл**: он идёт через
веб-сервис (`rag_service.py`) или MCP-сервер (`rag_mcp.py`), см. README.

## Главное правило: аннотацию пишешь ты

Инструмент сам ничего не выдумывает: он разбирает файл (название,
структура, оглавление, текст), а **аннотацию (2-4 предложения) и, если
нужно, название — пишешь ты, модель сессии**. Так в базу попадает
осмысленное описание, а не первая попавшаяся строка файла. Передавай
аннотацию через `--annotation`, а не через stdin — так позже видно, что
именно было записано.

## Директория системы

Инструмент лежит в директории personal_rag. Определи директорию через
переменную скилла `RAG_DIR` так:

    RAG_DIR="${PERSONAL_RAG_DIR:-.}"

`PERSONAL_RAG_DIR` — переменная окружения, указывающая на каталог
personal_rag; её обычно задают один раз в профиле или в конфиге OpenCode
проекта. Если переменной нет — считается, что OpenCode запущен в самом
каталоге personal_rag (или что он лежит в текущем каталоге).

`config.toml` ищется рядом с `rag_tool.py`, а не в текущей директории:
каталог документов и база всегда те, что записаны в конфиге, откуда бы
скилл ни запускался.

Проверь, что директория найдена, — первая же команда:

    "$RAG_DIR/rag_tool.py" list

Если файла нет и `PERSONAL_RAG_DIR` не задана — спроси у пользователя,
где лежит personal_rag, и не угадывай путь сам.

## Добавление документа

1. Покажи сводку, ничего не записывая:

   ```bash
   "$RAG_DIR/rag_tool.py" inspect путь/к/файлу.md
   ```

   В ответе: `title`, `toc` (оглавление), `lang`, `chars`, `head`
   (начало текста). По ним и пиши аннотацию — весь файл читать не нужно.
   Если в `warning` сказано, что файла нет или это скан — скажи об этом
   пользователю и остановись.

2. Напиши аннотацию: 2-4 предложения на языке документа, по существу
   (что это, о чём, чем полезно). Не пересказывай заголовки — добавь то,
   чего в них нет.

3. Положи в базу:

   ```bash
   "$RAG_DIR/rag_tool.py" add путь/к/файлу.md --annotation "…" [--title "…"]
   ```

   `--title` нужен, только если первый заголовок файла — плохое название
   (например, «Протокол» вместо «Протокол совещания 12.03»). Файл вне
   каталога документов инструмент скопирует сам; имя-конфликт разрешит
   суффиксом, не перезаписывая чужой файл.

## Обновление

```bash
"$RAG_DIR/rag_tool.py" scan              # что изменилось в каталоге?
"$RAG_DIR/rag_tool.py" update путь/к/файлу.md
```

`update` сам замечает, что хеш файла тот же, и не тратит эмбеддинги
зря (`updated: false`). Если содержание изменилось существенно —
перепиши и аннотацию: `update … --annotation "…"`. `scan --apply`
переиндексирует изменённые файлы, оставив прежние аннотации, — это
быстрый путь, когда аннотации всё ещё верны.

## Удаление

```bash
"$RAG_DIR/rag_tool.py" remove путь/к/файлу.md     # или remove 3 (по id)
```

Удаляется запись из базы, сам файл в каталоге остаётся. Если пользователь
просит «удали файл» — уточни: из базы или с диска. Скилл удаляет только
из базы; с диска файл удаляет сам пользователь.

## Что проверять после любой команды

Все команды печатают JSON. Проверяй:

- `added.chunks` / `doc.chunks` — если 0, текст не извлекся (скан?),
  сообщи пользователю;
- `warning` в `inspect` — предупреждения инструмента;
- код возврата: ненулевой и текст в stderr — команда не прошла, причина
  в stderr, повтори её не нужно, скажи пользователю.

Не запускай `add` и `update` параллельно: база — один sqlite-файл,
одновременные записи в неё ни к чему.
